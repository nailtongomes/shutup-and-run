## Known risks, checked against the code

Every item in the "Known risks" section of HANDOFF.md is still true as written. Nothing there is worse in the code than the section says.

- Host config: `src/bollard_rt.rs:145-156` sets only `auto_remove`, cpu, memory, memory swap, and shm. The request struct in `src/api.rs:276-289` rejects unknown fields, so a caller cannot set privileged, binds, devices, pid, network mode, capabilities, or ports.
- Auth: the ban is checked before the token (`src/api.rs:37-43`). The compare is SHA-256 plus `subtle` (`src/auth.rs:26-29`). The middleware wraps the whole router, and an unknown path with a valid token is `404`.
- Callback: scheme and host are checked, redirects are off, and there is no private address block (`src/callback.rs:6-18`). The response body is not read.
- Poll: body capped at 64 KiB, redirects off, userinfo rejected (`src/poll.rs:149-163`, `src/config.rs`).
- Workflows: `image.yml` has `contents: read` and `packages: write`. `release.yml` has `contents: write`. Neither has more than it uses.
- Panics: the request path has no `unwrap` outside the SQLite mutex `expect` already listed. The `unwrap` on the certificate paths in `src/main.rs` is guarded by the check above it.

## Issue text for the deferred findings

### M1. No per-address connection limit on the TLS listener

Silent connections are now closed after 10 seconds, but one host can keep opening new ones and a connection that never sends a request is never banned. The process has no connection cap. The intended fix is outside the binary: a firewall rule that only admits the orchestrator. If that is not enough, add a cap on concurrent connections per peer address in `src/main.rs`.

### M2. A single-word allowlist entry also allows `name:port/anything`

`image_allowed` in `src/allowlist.rs` accepts any suffix that starts with `:`. With the entry `alpine`, the image `alpine:5000/evil` passes and Docker treats `alpine:5000` as a registry host. Reject a `/` after the entry. Entries with a registry and a namespace are not affected, because Docker refuses the resulting name.

### M3. A tag-pinned allowlist entry does not pin the image

With the entry `ghcr.io/you/worker:1.0`, the image `ghcr.io/you/worker:1.0@sha256:<digest>` is allowed and Docker pulls the digest, whatever tag it belongs to. When the entry carries a tag, accept only the exact string.

### M4. `tail_logs` buffers without a limit

`BollardRuntime::tail_logs` appends every chunk Docker returns. The line count is bounded, the bytes are not. Trim the buffer to the last 256 KiB inside the loop, the same limit `clip_logs` applies afterwards.

### M5. A container exit can be missed while the event stream reconnects

`spawn_exit_watcher` sleeps 2 seconds between streams and does not look back. Run `launcher.reconcile()` each time the stream is opened again so rows are closed and callbacks are sent.

### M6. `ci.yml` does not restrict its token

Add a top-level `permissions: contents: read` to `.github/workflows/ci.yml`.

### L1. Image pull happens before the slot check

A full machine still pulls before it answers `429`, which slows the failover the orchestrator relies on. Add an early `running_count` check before `runtime.pull` in `Launcher::launch`. Keep the check under the mutex as it is.

### L2. Auth failure counts never expire

Add a `last_failure` column to `auth_failures`, reset the count when the last failure is older than `ban_hours`, and delete old rows in the purge pass.

### L3. Plain HTTP listener has no request deadline

`axum::serve` has no timeout settings. Plain HTTP is documented as localhost only. Leave it, or serve it through `axum_server::bind` with the same two deadlines as TLS.

### L4. Workflow actions are not pinned and checkout keeps the token

Pin each `uses:` to a commit SHA. Add `persist-credentials: false` to `actions/checkout` in `release.yml` and `image.yml`.

### L5. Installer can overwrite the env file

In `scripts/install.sh`, append `SHUTUP_AND_RUN_TOKEN=...` when the file exists without it.

### L6. Certificate expiry is silent

Log the certificate's `notAfter` next to the fingerprint at startup, or document renewal: delete `cert.pem` and `key.pem`, run the installer again, and send the new fingerprint to the callers.

### L7. Token visible in the process list during install

Write the header to a mode 600 temporary file and use `curl -H @file` in the installer's health loop.
